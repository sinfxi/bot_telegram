## 👀 یک سناریوی واقعی

فرض کن یک نفر تازه وارد گروه شده.

CAPTCHA روشن است؛ پس قبل از اینکه شروع کند به فرستادن پیام، باید خودش را تأیید کند.

حالا یک نفر لینک تبلیغاتی می‌فرستد:

```
🔗 پیام شناسایی شد
        ↓
🛡️ Anti-Link
        ↓
🗑️ حذف پیام
```

یکی هم شروع می‌کند پشت سر هم پیام فرستادن:

```
⚡ رفتار مشکوک
        ↓
🛡️ Anti-Spam
        ↓
🚨 واکنش ربات
```

و اگر کسی قوانین گروه را جدی نگیرد:

```
⚠️ اخطار اول
      ↓
⚠️ اخطار دوم
      ↓
🚨 اخطار سوم
      ↓
🔒 محدودسازی
```

در طرف دیگر، ادمین همه این‌ها را کنترل می‌کند.

**ایده اصلی پروژه همین است: یک ربات، چندین ابزار مدیریتی.**

# 🧠 سیستم Warning

Warning فقط یک عدد نیست.

برای هر گروه و کاربر جداگانه نگهداری می‌شود و بعد از رسیدن به حد مشخص، ربات می‌تواند محدودسازی را انجام دهد.

مثلاً:

```
User
 │
 ├── ⚠️ 1
 │
 ├── ⚠️ 2
 │
 └── 🚨 3
       │
       └── 🔒 Restrict
```

این بخش با SQLite ذخیره می‌شود تا وضعیت اخطارها بین اجرای برنامه باقی بماند.

# 📝 Notes؛ کوچک ولی کاربردی

فرض کن قوانین گروه را بارها باید برای کاربران بفرستی.

یک بار ذخیره‌اش کن:

```
/note rules قوانین کامل گروه...
```

بعد هر وقت لازم شد:

```
/getnote rules
```

تمام.

برای قوانین، FAQ، پاسخ‌های آماده و پیام‌های پرتکرار خیلی به درد می‌خورد.

# 🚀 وضعیت فعلی پروژه

این ربات الان فقط یک نمونه اولیه نیست؛ بخش‌های اصلی مدیریت، امنیت و ابزارهای مدیریتی گروه در آن پیاده‌سازی شده و آماده استفاده است.

## 🛡️ مدیریت اعضا و دسترسی‌ها
امکان مدیریت مستقیم اعضای گروه با دستورهای مدیریتی:

- `/ban` — مسدود کردن کاربر
- `/unban` — رفع مسدودی کاربر
- `/mute [minutes]` — محدود کردن کاربر برای مدت مشخص
- `/unmute` — رفع محدودیت کاربر
- `/promote` — ارتقای کاربر به ادمین
- `/demote` — حذف دسترسی ادمینی
- `/del` — حذف پیام
- `/pin` — سنجاق کردن پیام

---

## ⚠️ سیستم Warning
برای هر کاربر در هر گروه، تعداد اخطارها به‌صورت جداگانه ثبت می‌شود. با رسیدن کاربر به **۳ اخطار**، ربات به‌صورت خودکار او را برای **۶۰ دقیقه محدود** می‌کند.

دستورات:

- `/warn` — ثبت اخطار برای کاربر
- `/warnings` — مشاهده اخطارهای کاربر
- `/clearwarn` — پاک کردن اخطارهای کاربر

---

## 🔗 Anti-Link
ربات پیام‌هایی که شامل لینک‌های اینترنتی، `http://`، `https://`، `t.me/` یا `www.` باشند را شناسایی می‌کند و در صورت فعال بودن قابلیت، پیام را حذف می‌کند.

دستورات:

- `/antilink on` — فعال کردن Anti-Link
- `/antilink off` — غیرفعال کردن Anti-Link

---

## ⚡ Anti-Spam
رفتارهای پیام‌دادن سریع و پشت‌سرهم بررسی می‌شوند. اگر کاربر در مدت کوتاه تعداد زیادی پیام ارسال کند، ربات آن را به‌عنوان رفتار اسپمی تشخیص داده و می‌تواند کاربر را به‌صورت خودکار برای **۵ دقیقه محدود** کند.

دستورات:

- `/antispam on` — فعال کردن Anti-Spam
- `/antispam off` — غیرفعال کردن Anti-Spam

---

## 🤖 CAPTCHA برای اعضای جدید
وقتی CAPTCHA فعال باشد، اعضای جدید قبل از ارسال پیام باید تأیید شوند. درخواست CAPTCHA حداکثر **۵ دقیقه** اعتبار دارد و پس از آن منقضی می‌شود.

دستورات:

- `/captcha on` — فعال کردن CAPTCHA
- `/captcha off` — غیرفعال کردن CAPTCHA

---

## 🚫 فیلتر کلمات
ادمین می‌تواند کلمات مشخصی را برای هر گروه تعریف کند. پیام‌هایی که شامل کلمات فیلترشده باشند شناسایی شده و در صورت فعال بودن قابلیت، پیام حذف می‌شود.

دستورات:

- `/filter <word>` — اضافه کردن کلمه به فیلتر
- `/unfilter <word>` — حذف کلمه از فیلتر
- `/filters` — نمایش فهرست کلمات فیلترشده

---

## 👋 Welcome و Rules
امکان فعال یا غیرفعال کردن پیام خوش‌آمدگویی برای اعضای جدید و نمایش قوانین گروه وجود دارد تا مدیریت ورود کاربران و اطلاع‌رسانی قوانین ساده‌تر شود.

دستورات:

- `/welcome on` — فعال کردن Welcome
- `/welcome off` — غیرفعال کردن Welcome
- `/rules` — نمایش قوانین گروه

---

## 📝 سیستم Notes
متن‌های پرتکرار مثل قوانین، FAQ یا پاسخ‌های آماده را می‌توان با یک نام ذخیره کرد و بعداً با دستور مربوطه دوباره دریافت کرد؛ بدون اینکه لازم باشد متن را هر بار از ابتدا بنویسی.

دستورات:

- `/note <name> <text>` — ساخت Note جدید
- `/getnote <name>` — دریافت Note
- `/notes` — نمایش Noteهای ذخیره‌شده
- `/id` — نمایش شناسه کاربر/گروه

مثال:

```text
/note rules لطفاً قوانین گروه را رعایت کنید.
/getnote rules
```

---

## 📊 آمار و Action Logs
ربات اطلاعات مدیریتی مانند تعداد کاربران ثبت‌شده، اخطارها، فیلترها، CAPTCHAهای در انتظار و فعالیت‌های مدیریتی را نگهداری می‌کند. اقدامات مهم نیز در Action Logs ثبت می‌شوند.

دسترسی به اطلاعات مدیریتی:

- `/admin` — باز کردن پنل مدیریت
- پنل Inline — مشاهده آمار، کاربران، امنیت و لاگ‌های مدیریتی

---

## 📢 Broadcast
ادمین اصلی می‌تواند یک پیام را برای کاربران ثبت‌شده ارسال کند؛ بنابراین برای اطلاع‌رسانی عمومی لازم نیست پیام را جداگانه برای هر کاربر بفرستد.

دستورات:

- `/broadcast` — شروع Broadcast
- `/cancel` — لغو Broadcast

---

## 👑 پنل مدیریتی Inline
بخش مدیریتی ربات فقط به دستورات متنی محدود نیست. یک پنل Inline برای مشاهده آمار، کاربران، وضعیت امنیت و امکانات ربات در نظر گرفته شده تا دسترسی به بخش‌های مدیریتی راحت‌تر باشد.

دستور اصلی:

- `/admin` — باز کردن پنل مدیریت

---

## 💾 ذخیره اطلاعات با SQLite
اطلاعات اصلی ربات مانند کاربران، تنظیمات گروه، Warningها، Notes، فیلترها، لاگ‌ها و وضعیت‌های موقت در SQLite نگهداری می‌شوند و برای عملکرد دیتابیس از حالت WAL نیز استفاده شده است.

اطلاعاتی که مدیریت می‌شوند شامل:

- 🚫 فیلتر کلمات
- 📝 Notes
- 📊 Action Logs
- 🤖 CAPTCHAهای در انتظار
- 🔇 محدودیت‌های موقت
- ⚡ داده‌های Anti-Spam

## 🤖 دستیار هوش مصنوعی

- گفتگوی فارسی خودمانی در چت خصوصی؛ در گروه فقط با Reply به ربات یا اشاره به نام کاربری آن پاسخ می‌دهد.
- هفت لحن: خاکی و خودمونی، شوخ، ریلکس، حرفه‌ای، انگیزشی، گیمر و کوتاه.
- حافظه کوتاه گفتگو برای هر کاربر؛ پاک‌سازی با دستور `/clearchat`.
- کنترل روشن/خاموش از `/ai on` و `/ai off` و از پنل `/admin`.
- برای فعال شدن پاسخ‌های مدل، متغیر محیطی `OPENAI_API_KEY` را در Railway برای سرویس `telegram-bot` اضافه کن. اختیاری: `OPENAI_MODEL` (پیش‌فرض `gpt-5.5`). کلید را داخل کد یا GitHub قرار نده.

### دستورات هوش مصنوعی

```text
/ai on
/ai off
/style
/clearchat
/admin
```
