# Telegram Delete Assistant Pro 🛡️

ابزار فارسی برای مدیریت و راهنمایی فرایند حذف حساب تلگرام، همراه با ربات تلگرامی و پنل مدیریتی وب. این پروژه با هدف ارائه رابط روشن، تنظیمات متمرکز و کنترل دسترسی مدیر طراحی شده است.

> **وضعیت پروژه:** این فایل هدف و ساختار مورد انتظار پروژه را معرفی می‌کند؛ وجود هر قابلیت در نسخهٔ مستقر باید با کد و تست همان نسخه تأیید شود. تغییر README به‌تنهایی به معنی رفع باگ یا انتشار نسخهٔ جدید نیست.

## معرفی

Telegram Delete Assistant Pro برای فراهم‌کردن تجربه‌ای ساده‌تر در دسترسی به قابلیت‌های ربات و مدیریت تنظیمات آن ساخته می‌شود. پنل وب باید امکان مشاهده و تنظیم قابلیت‌های پشتیبانی‌شدهٔ ربات را در یک محل فراهم کند و با API بک‌اند ارتباط امن داشته باشد.

## قابلیت‌ها و اهداف

- رابط فارسی برای استفاده از ربات و پنل وب.
- پنل مدیریتی مستقل برای تنظیم قابلیت‌های پشتیبانی‌شدهٔ ربات.
- ورود مدیر با شناسهٔ عددی و رمز عبور، در صورت پیکربندی و پیاده‌سازی در نسخهٔ جاری.
- کنترل دسترسی سمت سرور برای مسیرهای مدیریتی؛ مخفی‌کردن دکمه‌ها به‌تنهایی جایگزین احراز هویت نیست.
- پشتیبانی از تنظیمات و وضعیت‌های ربات از طریق API.
- امکان اتصال به OpenRouter برای قابلیت‌های هوش مصنوعیِ موردنیاز پروژه؛ سایر قابلیت‌های هوش مصنوعی باید غیرفعال یا حذف شوند، مطابق تنظیمات و نسخهٔ جاری.
- endpoint سلامت سرویس برای بررسی وضعیت اجرا، در صورت فعال‌بودن در نسخهٔ مستقر.
- امکان استقرار روی سرویس‌هایی مانند Render، پس از تنظیم متغیرهای محیطی و فرمان اجرای درست.

## پنل وب و خطاهای اتصال

اگر پنل خطای «درخواست بین‌مبدأیی مجاز نیست» یا CORS نشان دهد، مقدار Origin رابط کاربری باید با فهرست مبدأهای مجاز بک‌اند هماهنگ شود. مجازکردن مبدأها باید صریح و محدود به دامنه‌های مورداعتماد باشد؛ استفاده از wildcard برای پنل دارای نشست یا اطلاعات مدیریتی توصیه نمی‌شود.

برای بررسی نسخهٔ مستقر، صفحهٔ اصلی پنل، مسیر سلامت سرویس (اگر پیاده‌سازی شده) و درخواست‌های API باید جداگانه آزمایش شوند. سبز بودن health check به‌تنهایی صحت ورود مدیر یا کارکرد همهٔ دکمه‌های پنل را ثابت نمی‌کند.

## پیکربندی و امنیت

نام متغیرهای محیطی باید با کد واقعی پروژه مطابقت داشته باشد. متغیرهای رایج ممکن است شامل موارد زیر باشند:

- `BOT_TOKEN`: توکن ربات تلگرام.
- `ADMIN_ID`: شناسهٔ عددی مدیر مجاز.
- `ADMIN_PASSWORD`: رمز مدیر، فقط اگر ورود مبتنی بر رمز در کد پشتیبانی شود.
- `OPENROUTER_API_KEY`: کلید OpenRouter، فقط اگر این قابلیت در نسخهٔ جاری فعال باشد.
- `DATABASE_URL`: آدرس پایگاه داده، در صورت استفاده از دیتابیس.
- `PORT`: پورت اختصاص‌داده‌شده توسط میزبان، در صورت نیاز.

این نام‌ها نمونه‌اند؛ قبل از تنظیم سرویس، آن‌ها را با کد و تنظیمات استقرار پروژه تطبیق بده.

### نکات امنیتی مهم

- توکن ربات، رمز مدیر و کلید API را داخل کد، README یا commit قرار نده؛ آن‌ها را در Environment Variables میزبان نگه دار.
- اگر کلیدی قبلاً منتشر شده، آن را تعویض کن.
- endpointهای مدیریتی باید در بک‌اند احراز هویت و مجوز مدیر را بررسی کنند.
- برای ورود، از رمز قوی و انتقال HTTPS استفاده کن.
- فقط قابلیت‌هایی را فعال معرفی کن که در کد پیاده‌سازی و آزمایش شده‌اند.

## استقرار روی Render

1. مخزن و شاخهٔ صحیح پروژه را به سرویس Render متصل کن.
2. Runtime، Build Command و Start Command را مطابق فایل‌های واقعی پروژه تنظیم کن.
3. متغیرهای محیطی موردنیاز را در تنظیمات سرویس وارد کن.
4. پس از Deploy، لاگ‌های Build و Runtime را بررسی کن.
5. پنل، ورود مدیر، درخواست‌های API و CORS را از دامنهٔ واقعی آزمایش کن.

## گزارش مشکل

برای گزارش خطا، این اطلاعات مفیدند:
- آدرس صفحه‌ای که خطا می‌دهد.
- متن خطا و status code درخواست API.
- Origin درخواست و مسیر endpoint (بدون ارسال توکن، کوکی یا رمز).
- لاگ مرتبط با زمان رخداد، پس از حذف اطلاعات محرمانه.
