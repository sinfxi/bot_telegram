# FXI Cloudflare Worker — migration foundation

این پوشه یک مسیر مهاجرت مستقل است و جایگزین نسخه تولیدی Render نیست. تمام تغییرات فقط روی شاخه `cloudflare-free-migration` انجام می‌شوند.

## پیاده‌سازی‌شده در این مرحله
- endpointهای `/health` و `/ready`
- اعتبارسنجی secret وب‌هوک تلگرام و ثبت updateها در D1
- احراز هویت مالک با OTP شش‌رقمی تلگرام و شناسه مالک
- احراز هویت مدیر با نام کاربری و OTP شش‌رقمی تلگرامِ متصل به حساب
- ذخیره challenge و session در D1؛ کوکی تصادفی فقط به‌شکل هش در دیتابیس ذخیره می‌شود
- کوکی نشست `HttpOnly; Secure; SameSite=Strict` با انقضای هفت‌روزه
- انقضای OTP پس از ۶۰ ثانیه، حداکثر ۵ تلاش، محدودیت درخواست و ثبت رویدادهای ورود
- ابطال نشست جاری هنگام خروج و پشتیبانی از نسخه نشست مالک برای ابطال سراسری نشست‌های او
- بررسی نقش و سطح دسترسی مدیر در سمت سرور؛ مسیرهای نامشخص برای مدیر با سیاست fail-closed رد می‌شوند
- محافظت Origin برای درخواست‌های تغییردهنده وضعیت پنل

## هنوز منتقل نشده
- رابط HTML پنل مالک و مدیر
- APIهای واقعی مدیریت گروه/کانال، پیام همگانی، گزارش‌ها و تنظیمات
- مدیریت مدیران و گردش کامل دعوت/تأیید مدیر
- handlerهای اصلی ربات، OpenRouter، صف زمان‌بندی و پردازش کامل وب‌هوک
- مهاجرت داده‌های PostgreSQL و تطبیق کامل schema با داده واقعی Render

در نتیجه ورود و احراز هویت در این مرحله زیرساختی است؛ هنوز پنل کامل یا ربات قابل استفاده تولیدی نیست. مسیرهای پنلِ منتقل‌نشده عمداً پاسخ `501` می‌دهند و هیچ عملیات ساختگی انجام نمی‌دهند.

## تنظیمات محیطی

این مقادیر را فقط به‌صورت secret یا متغیر محیطی Worker تنظیم کن؛ هیچ‌کدام را در Git commit نکن:

- `TELEGRAM_BOT_TOKEN`: توکن ربات
- `TELEGRAM_WEBHOOK_SECRET`: secret وب‌هوک با قالب مجاز تلگرام
- `OWNER_TELEGRAM_ID`: شناسه عددی مالک
- `AUTH_PEPPER`: مقدار تصادفی بلند و محرمانه برای هش OTP و شناسه IP
- `APP_ORIGIN`: مبدأ دقیق پنل، مانند `https://panel.example.com`

برای OTP، مالک و مدیر باید قبلاً ربات را در تلگرام Start کرده باشند. رمز یا کد ورود نباید در لاگ یا پاسخ API ثبت شود.

## اجرای محلی

1. Node.js را نصب کن و در همین پوشه `npm install` را اجرا کن.
2. در مسیر همین پوشه، فایل `.dev.vars` بساز و مقادیر محیطی بالا را در آن قرار بده. این فایل را commit نکن.
3. migrationها را فقط روی دیتابیس محلی اجرا کن:

   `npx wrangler d1 migrations apply fxi_bot_prod --local`

4. بررسی نوع‌ها و خطاهای TypeScript:

   `npm run check`

5. اجرا:

   `npm run dev``

6. `GET /health` و `GET /ready` را بررسی کن. برای تست ورود، APP_ORIGIN باید دقیقاً با origin محیط آزمایش یکی باشد.

## محدودیت‌های ایمنی و انتشار

- migration از راه دور اجرا نشده و D1 تولیدی همچنان بدون جدول است.
- Worker deploy نشده و Telegram webhook ثبت نشده است.
- Render و PostgreSQL فعلی دست‌نخورده باقی می‌مانند.
- تا زمان تهیه و راستی‌آزمایی backup، تطبیق schema، انتقال قابلیت‌ها و آزمون rollback از `--remote`، `wrangler deploy` یا `setWebhook` استفاده نکن.
- سرویس پولی Cloudflare فعال نشده است.
