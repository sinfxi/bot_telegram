# مرحله اول انتقال قابلیت‌های گروه و کانال به Cloudflare

تاریخ: 2026-11-08  
شاخه: `cloudflare-free-migration`

## محدوده این مرحله

این مرحله فقط کد را روی شاخه مهاجرت آماده کرده است؛ هیچ Worker یا webhook تولیدی فعال نشده و هیچ تغییری در Render ایجاد نشده است.

### پیاده‌سازی‌شده در Worker

- دریافت پیام‌های گروه، سوپرگروه و پست‌های کانال از مسیر webhook.
- ذخیره پیام‌های متنی در جدول `community_messages` برای آرشیو و آمار پایه.
- ذخیره تنظیمات مستقل هر گروه/کانال در `community_chat_settings`.
- ثبت واژه‌های مسدودشده در `community_blocked_words`.
- فیلتر لینک و واژه، با امکان حذف پیام در صورت فعال‌بودن تنظیم مربوطه.
- محدودیت ضدسیل بر اساس تعداد پیام‌های هر کاربر در بازه ۳۰ ثانیه.
- خوشامدگویی هنگام ورود عضو، مشروط به فعال بودن تنظیم.
- بررسی مدیر بودن کاربر در همان گروه از طریق Telegram `getChatMember`؛ مالک سراسری به‌تنهایی مجوز مدیریت گروه را دور نمی‌زند.
- عملیات ریپلای‌محور پین، آنپین، حذف، سکوت، رفع سکوت، بن و رفع بن.
- ثبت و نمایش قوانین و آمار پایه پیام‌ها.
- ثبت وضعیت پردازش webhook و امکان بازیابی updateهای شکست‌خورده یا پردازش‌های رهاشده پس از ۱۲۰ ثانیه.

### جداول جدید

Migrationهای `0004_community_operations.sql` و `0005_webhook_retry_lease.sql` به ترتیب جداول تنظیمات گروه، واژه‌های مسدود، اخطارها، رویدادهای ضدسیل و metadata اجاره پردازش webhook را اضافه می‌کنند.

## کنترل کیفیت

- GitHub Actions برای commit مربوط به اضافه‌شدن handlerها، اجرای `npm run check` و اعمال migrationهای D1 به‌صورت local را با موفقیت گذرانده است.
- CI برای commitهای بعدی نیز اجرا شده است؛ وضعیت نهایی آخرین run را در Actions بررسی کنید.
- این بررسی، تست end-to-end با Telegram واقعی یا تست مرورگر نیست.
- هیچ migration روی D1 تولیدی اجرا نشده است.

## محدودیت‌ها و کارهای باقی‌مانده

- برای دریافت `chat_member`، `edited_message` و `edited_channel_post` باید در زمان cutover مقدار `allowed_updates` وب‌هوک با این رویدادها تنظیم شود. هنوز وب‌هوک تنظیم نشده است.
- کنترل تنظیمات از طریق عبارت‌های طبیعی هنوز کامل نیست؛ در این مرحله فرمان «تنظیمات» وضعیت فعلی را نشان می‌دهد.
- داشبوردهای مدیریتی هنوز APIهای عملیاتی گروه/کانال را ندارند؛ endpointهای عملیاتی مدیر و مالک باید با مجوزهای سمت سرور متصل شوند.
- تحلیل پست‌های برتر با واکنش‌ها/بازدیدها، پیشنهادهای محتوایی OpenRouter، پیش‌نویس و تقویم محتوا هنوز منتقل نشده‌اند.
- پیام همگانی، صف ارسال، بارگذاری تصویر، زمان‌بندی و گزارش تحویل هنوز منتقل نشده‌اند.
- سیستم اخطار و ارتقای خودکار اخطار به محدودیت، در این slice هنوز منتقل نشده است.
- برای جلوگیری از تکرار side-effect در سناریوی «Telegram درخواست را اجرا کرده اما پاسخ شبکه گم شده»، باید Outbox پایدار و idempotency اختصاصی عملیات اضافه شود. Lease فعلی فقط از پردازش هم‌زمان عادی و گیرکردن دائمی update جلوگیری می‌کند؛ تضمین exactly-once برای فراخوانی‌های Telegram ایجاد نمی‌کند.
- پاکسازی دوره‌ای `community_flood_events` و سیاست نگهداری آرشیو باید با Cron اضافه شود.

## ایمنی انتشار

تا تکمیل backup کامل PostgreSQL، تطبیق schema و انتقال داده، تست تمام قابلیت‌ها و تأیید صریح مالک:
- Worker را Deploy نکنید.
- webhook تلگرام را تغییر ندهید.
- Migration ریموت D1 اجرا نکنید.
- Render و دیتابیس فعلی را حذف یا متوقف نکنید.
- هیچ سرویس پولی Cloudflare فعال نکنید.
