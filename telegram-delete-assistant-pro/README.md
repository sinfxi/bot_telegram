# FXI Telegram Automation

سامانهٔ خودکارسازی کنترل‌شده برای **حساب شخصی تلگرام** همراه با ربات مدیریتی و پنل وب فارسی. نسخهٔ فعلی از Telethon برای کلاینت حساب شخصی و از aiogram برای ربات مدیریتی استفاده می‌کند.

## قابلیت‌ها

- اتصال حساب شخصی تلگرام از پنل وب محافظت‌شده با HTTP Basic Authentication
- فرایند ورود با شماره، کد تأیید و در صورت نیاز رمز دومرحله‌ای
- ذخیرهٔ نشست تلگرام به‌صورت رمزگذاری‌شده با Fernet؛ کلید رمزگذاری فقط در متغیر محیطی قرار می‌گیرد
- ساخت قانون پاسخ‌گویی با عبارت محرک و تطبیق «شامل عبارت» یا «دقیق»
- فهرست‌سازی مخاطب‌ها و انتخاب دستی مخاطب‌های مجاز
- پاسخ خودکار فقط به پیام خصوصی مخاطب‌هایی که مدیر صریحاً مجاز کرده است
- پیام زمان‌بندی‌شده برای گیرندهٔ مشخص از پنل وب
- توقف/فعال‌سازی خودکارسازی، وضعیت، قوانین و رویدادهای اخیر
- ربات مدیریتی با فرمان‌های `/start`، `/status`، `/rules`، `/pause`، `/resume` و `/help`

## محدودیت‌ها و رفتار ایمن

- این سامانه فقط برای حسابی است که مالک آن هستی. پیام‌های خودکار فقط برای مخاطب‌های مجازشده ارسال می‌شوند؛ ارسال انبوه و پیام‌دادن خودکار به همهٔ مخاطب‌ها پیاده‌سازی نشده است.
- کد ورود و رمز دومرحله‌ای را در چت ربات وارد نکن؛ آن‌ها فقط در پنل HTTPS محافظت‌شده وارد می‌شوند. اطلاعات ورود در لاگ ثبت نمی‌شود.
- نشست حساب به‌صورت رمزگذاری‌شده در دیتابیس نگهداری می‌شود. اگر `SESSION_ENCRYPTION_KEY` گم یا عوض شود، نشست ذخیره‌شده قابل رمزگشایی نیست و باید حساب دوباره متصل شود.
- برای اتصال حساب شخصی به `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` خودت نیاز داری که از پورتال رسمی Telegram API دریافت می‌شوند.
- این پروژه حساب را از طریق Bot API کنترل نمی‌کند؛ ربات مدیریتی و کلاینت حساب شخصی دو اتصال مجزا هستند.

## متغیرهای محیطی

| نام | کاربرد |
|---|---|
| `BOT_TOKEN` | توکن ربات مدیریتی از BotFather |
| `ADMIN_ID` | شناسهٔ عددی حساب تلگرام مدیر ربات |
| `ADMIN_USER` / `ADMIN_PASSWORD` | دسترسی پنل وب؛ رمز قوی و منحصربه‌فرد انتخاب کن |
| `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` | اطلاعات API برای کلاینت حساب شخصی |
| `SESSION_ENCRYPTION_KEY` | کلید Fernet برای رمزگذاری نشست ذخیره‌شده |
| `DB_PATH` | مسیر دیتابیس؛ پیش‌فرض `/data/bot.sqlite3` |
| `PORT` | پورت وب که میزبان تعیین می‌کند |
| `PUBLIC_BASE_URL` | آدرس عمومی پنل که در پیام ربات نمایش داده می‌شود |

برای ساخت کلید Fernet می‌توانی محلی اجرا کنی:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

کلید را فقط در Environment سرویس Render ذخیره کن و آن را در GitHub یا چت نفرست.

## اجرای محلی

```bash
python -m pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 8000
```

## Render

Build command:

```bash
pip install -r telegram-delete-assistant-pro/requirements.txt
```

Start command:

```bash
uvicorn app:app --app-dir telegram-delete-assistant-pro --host 0.0.0.0 --port $PORT
```

یک فضای ذخیره‌سازی پایدار را به `/data` متصل کن و فقط یک نمونه از سرویس اجرا کن؛ اجرای هم‌زمان چند نمونه می‌تواند polling ربات و نشست کلاینت را دچار تعارض کند. مسیر `/health` برای بررسی سلامت عمومی سرویس است و پنل اصلی با HTTP Basic محافظت می‌شود.

## مسیرهای پنل

- `/` داشبورد
- `/account` اتصال/قطع حساب
- `/contacts` همگام‌سازی و مجازکردن مخاطب‌ها
- `/rules` ساخت و مدیریت قوانین
- `/schedule` پیام‌های زمان‌بندی‌شده
- `/health` بررسی سلامت

قبل از استفادهٔ واقعی، تنظیمات Environment را بررسی کن و ابتدا با یک مخاطب آزمایشی که مجاز کرده‌ای، رفتار قوانین و زمان‌بندی را آزمایش کن.
