# FXI Telegram Community Manager

ربات مدیریت جامعهٔ تلگرام و دستیار چندمدلی FXI، همراه با پنل مدیریت فارسی و API مبتنی بر FastAPI.

## امکانات

- پاسخ‌گویی هوشمند متنی و تحلیل تصویر رسید فقط از طریق OpenRouter؛ هیچ ارائه‌دهندهٔ هوش مصنوعی دیگری در نسخه فعلی پیکربندی یا استفاده نمی‌شود.
- تاریخچهٔ مکالمه با PostgreSQL و مدیریت نشست‌های چت.
- حالت پیش‌فرض پاسخ گروهی فقط هنگام منشن ربات یا ریپلای به پیام آن است. با روشن‌کردن «گفت‌وگوی رفاقتی» در تنظیمات هر گروه، ربات می‌تواند به پرسش‌ها و عبارت‌های محاوره‌ای مشخص هم پاسخ بدهد؛ پاسخ‌گویی به همه پیام‌ها به‌صورت بی‌وقفه انجام نمی‌شود.
- کنترل قابلیت‌های اصلی از پنل مدیریت؛ تبدیل گفتار به متن در نسخه OpenRouter-only غیرفعال است.
- فرمان‌های طبیعی فارسی برای روشن/خاموش‌کردن پاسخ هوشمند، مشاهدهٔ آمار، دریافت قوانین و تهیهٔ پیش‌نویس.
- ابزارهای مدیریت جامعه: قوانین، pin/delete، mute/unmute/ban، اخطار مرحله‌ای و سکوت ۳۰ دقیقه‌ای پس از رسیدن به سقف اخطار، ضدسیل با حذف پیام و محدودسازی ۵ دقیقه‌ای در تکرار، فیلتر واژه، کنترل اختیاری لینک‌ها، خوشامدگویی، آمار، گزارش کانال، پست‌های برتر، برنامهٔ محتوا و پیشنهادها.
- حالت گفت‌وگوی رفاقتی گروه با OpenRouter: پاسخ محاوره‌ای و شوخی محترمانه به سؤال‌ها و شروع گفتگوهای طبیعی، با زمینهٔ پیام‌های اخیر و محدودیت نرخ پاسخ برای جلوگیری از شلوغی؛ هوش مصنوعی خودش بن/حذف/تغییر تنظیمات انجام نمی‌دهد.
- کنترل جداگانهٔ فعال/غیرفعال‌بودن هر قابلیت گروه از فهرست تنظیمات پنل و دکمه‌های داخل گروه.
- پنل مدیریت: وضعیت سرویس، OpenRouter، کاربران و مدیران، مسدودسازی/فعال‌سازی دسترسی کاربران ربات، تاریخچهٔ مکالمه، بررسی درخواست‌ها، پیام همگانی، دستورالعمل مدل، تنظیم روشن/خاموش قابلیت‌ها، آمار جامعه، گزارش فعالیت‌های مدیریتی و خروجی CSV کاربران.
- پنل گروه‌ها و کانال‌ها: روشن/خاموش‌کردن قابلیت‌ها برای هر گروه، تنظیم سقف اخطار (۲ تا ۵)، ویرایش فهرست واژه‌های ممنوع تا ۱۰۰ مورد، کنترل لینک، ضداسپم و حالت گفت‌وگوی رفاقتی؛ همه از رابط گرافیکی و بدون نیاز به نوشتن دستور انجام می‌شود.
- گزارش مدیریتی محدود به ۵۰۰ رویداد اخیر؛ جزئیات حساس یا کلیدهای API در گزارش ذخیره نمی‌شوند.
- مسیر `/health` برای بررسی زنده‌بودن سرویس وب (liveness) و `/ready` برای بررسی آمادگی اتصال‌های ضروری (readiness)؛ `/admin/api/*` برای ابزارهای مدیریتی احراز هویت‌شده.

## اجرای محلی

نیازمندی: Python 3.11 یا جدیدتر.

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# مقدارهای واقعی را در فایل محلی .env قرار بده؛ این فایل را commit نکن.
uvicorn app:app --env-file .env --host 0.0.0.0 --port 8000
```

مقادیر `.env` را با تنظیمات خودت پر کن. در Windows می‌توانی متغیرها را از طریق تنظیمات Run/PowerShell یا یک ابزار بارگذاری dotenv تنظیم کنی. هیچ‌وقت توکن‌ها یا کلیدهای API را در GitHub ثبت نکن.

## متغیرهای اصلی

| متغیر | کاربرد |
|---|---|
| `ZEUS_BOT_TOKEN` | توکن ربات تلگرام از BotFather |
| `DATABASE_URL` | آدرس اتصال PostgreSQL؛ در Render مقدار Internal Database URL را وارد کن. برنامه جدول‌ها و ایندکس‌های خودش را هنگام راه‌اندازی خودکار می‌سازد. آدرس‌های قدیمی با پیشوند `postgres://` نیز پشتیبانی می‌شوند. |
| `TELEGRAM_BOT_USERNAME` | نام کاربری ربات بدون @؛ برای تشخیص خطاب مستقیم |
| `ADMIN_IDS` | شناسه‌های عددی مدیران اصلی، جداشده با کاما |
| `ADMIN_PANEL_USERNAME` | نام کاربری مالک اصلی پنل |\n| `ADMIN_PANEL_PASSWORD` | رمز عبور مالک اصلی پنل |\n| `SESSION_SECRET` | کلید تصادفی و ثابت برای امضای نشست‌های پنل |\n| `ADMIN_PANEL_URL` | آدرس عمومی پایهٔ پنل، بدون `/admin`؛ برای ساخت لینک‌های یک‌بارمصرف ادمین |
| `DATABASE_URL` | اتصال PostgreSQL برای وضعیت و تاریخچهٔ پایدار |
| `ADMIN_DATA_FILE` | مسیر فایل JSON جایگزین؛ در میزبانی ابری فایل موقت ممکن است با راه‌اندازی مجدد از بین برود |
| `AI_SYSTEM_PROMPT` | دستورالعمل اولیهٔ دستیار |
| `OPENROUTER_API_KEY` | کلید دسترسی تنها ارائه‌دهندهٔ هوش مصنوعی در این نسخه |

| `LOG_LEVEL` | سطح لاگ، مانند `INFO` |

برای پاسخ هوشمند و تحلیل تصویر رسید، `OPENROUTER_API_KEY` را تنظیم کن. قابلیت‌های قابل‌تنظیم از صفحهٔ «قابلیت‌های ربات» در پنل مدیریت ذخیره می‌شوند؛ پیام صوتی تا پیاده‌سازی سازگار با OpenRouter غیرفعال است.

## وضعیت مهاجرت به Cloudflare

مقصد استقرار این پروژه Cloudflare است. برای این مخزن هیچ استقرار جدیدی روی Render انجام ندهید.

- کد runtime آزمایشی Python Worker: `cloudflare-python/`
- پیکربندی Wrangler: `cloudflare-python/wrangler.toml`
- دیتابیس D1 آزمایشی: `fxi-telegram-assistant-stage`
- مسیر webhook آزمایشی: `POST /telegram/webhook`
- مسیر بررسی زنده‌بودن: `GET /health`
- مسیر آمادگی: `GET /ready`

**هشدار:** runtime جدید هنوز parity کامل با نسخه فعلی ندارد. پنل مالک، پنل مدیران، پنل مالک گروه، مدیریت کامل جامعه، مجوزها، backup/restore و تمام APIها باید قبل از cutover منتقل و تست شوند. Worker فعلی production و webhook اصلی تا آن زمان دست‌نخورده می‌مانند.

برای اجرای تست‌های runtime:

```bash
cd telegram-delete-assistant-pro/cloudflare-python
uv sync
uv run python -m compileall -q src tests
uv run pytest -q
```

برای استقرار staging، مقدار `CLOUDFLARE_API_TOKEN` را به‌صورت Repository Actions Secret در GitHub تنظیم و workflow زیر را اجرا کنید:

`Actions → FXI Telegram Cloudflare Python staging → Run workflow`

برای جزئیات معماری و فهرست کامل routeها، فایل‌های زیر را ببینید:

- `CLOUDFLARE_MIGRATION_AUDIT_FA.md`
- `CLOUDFLARE_FINAL_PARITY_MATRIX_FA.md`
- `cloudflare-python/README.md`

## فرمان‌های متنی طبیعی و صوتی

در گروه، برای حفظ حریم خصوصی ربات فقط صوتی را پردازش می‌کند که کپشن آن خطاب به ربات باشد یا در پاسخ به پیام ربات ارسال شده باشد. نمونه:
- با ریپلای به پیام: «پین»، «حذف»، «سکوت ۱۰ دقیقه»، «آزاد» یا «بن»
- «پاسخ هوشمند روشن» یا «پاسخ هوشمند خاموش»
- «آمار گروه»، «قوانین»، «ثبت قوانین متن دلخواه»، «تنظیمات»
- «گزارش کانال»، «پست‌های برتر»، «برنامه محتوا»، «چالش»، «پیشنهادها»
- «پیش‌نویس درباره امنیت»
- در گفت‌وگوی خصوصی: «انتخاب مدل»، «پاک کردن تاریخچه»، «حمایت» و «راهنما»

فرمان‌های مدیریتی مانند روشن/خاموش‌کردن AI، فعال‌کردن حالت گفت‌وگوی رفاقتی، ثبت قوانین، فیلتر واژه و اخطار فقط برای مدیران گروه اجرا می‌شوند. برای اخطار و پاک‌کردن اخطارها روی پیام عضو ریپلای کن. فیلتر لینک و فیلتر واژه به‌صورت پیش‌فرض خاموش‌اند و مدیر باید آن‌ها را در تنظیمات روشن کند. پیش‌نویس به‌صورت خودکار منتشر نمی‌شود.

برای اینکه ربات بتواند پیام‌های عادی گروه را برای گفت‌وگوی طبیعی دریافت کند، در BotFather از تنظیمات Bot Privacy گزینهٔ Group Privacy را خاموش کن یا ربات را با دسترسی مدیریتی مناسب اضافه کن. در غیر این صورت تلگرام فقط بخشی از پیام‌ها مثل منشن‌ها و ریپلای‌ها را به ربات می‌رساند. برای حذف پیام و محدودسازی اعضا نیز مجوزهای مدیریتی مربوطه لازم است.

### درخواست و ورود مدیر با کد یک‌بارمصرف

- برای درخواست مدیر، مالک از پنل یک لینک دعوت اختصاصی با توکن تصادفی ۲۵۶ بیتی و مهلت ۱۵ دقیقه می‌سازد. توکن خام فقط در لینک ارسالی است و در دیتابیس فقط SHA-256 آن ذخیره می‌شود؛ توکن داخل fragment لینک قرار می‌گیرد تا به درخواست HTTP، access log یا referrer ارسال نشود. متقاضی لینک را باز می‌کند، نام کاربری را وارد می‌کند و سپس حساب تلگرامش را از طریق deep link اختصاصی به درخواست متصل می‌کند. لینک فقط یک‌بار قابل مصرف است و مالک می‌تواند پیش از مصرف آن را لغو کند.
- پس از تأیید مالک، مدیر در صفحه ورود نام کاربری را وارد می‌کند و کد ۶ رقمی یک‌بارمصرف با اعتبار ۶۰ ثانیه به تلگرام متصل‌شده او ارسال می‌شود. رمز ثابت ذخیره نمی‌شود.
- پیام‌های موقت ربات در گروه (هشدارهای ضداسپم/فیلتر و پیام وضعیت تحلیل) و پیام‌های کد ورود مالک/مدیر پس از ۶۰ ثانیه پاک می‌شوند؛ پیام‌های کاربران، نتیجه‌های اصلی، اعلان تأیید مدیر، تاریخچه، تنظیمات و گزارش‌های مدیریتی پاک نمی‌شوند. پیام‌های موقت در آرشیو دائمی گروه هم ذخیره نمی‌شوند.
- هنگام ذخیره وضعیت، کدهای OTP منقضی‌شده، تلاش‌های محدودسازی قدیمی‌تر از یک دقیقه و داده‌های موقت غیرقابل‌استفاده پاک می‌شوند؛ گزارش مدیریتی حداکثر ۵۰۰ رکورد نگه می‌دارد. تاریخچه اصلی کاربران به‌صورت خودکار حذف نمی‌شود.
- مالک اصلی می‌تواند از بخش «سلامت و تنظیمات» یک خروجی پشتیبان JSONL از سه جدول برنامه (`fxi_bot_state`, `fxi_chat_messages`, `fxi_community_messages`) دانلود کند. این مسیر فقط با نشست مالک فعال است، داده‌ها را به‌صورت دسته‌ای از PostgreSQL می‌خواند، فایل موقت را پس از ارسال پاک می‌کند و سقف خروجی ۲۵۶ مگابایت دارد. فایل شامل داده‌های حساس و متن تاریخچه‌هاست و باید امن نگه‌داری شود. این قابلیت زمان‌بندی خودکار یا بازیابی (restore) انجام نمی‌دهد؛ برای بکاپ زمان‌بندی‌شده باید از پشتیبان‌گیری مدیریت‌شدهٔ میزبان PostgreSQL یا فضای ذخیره‌سازی خارجی پایدار استفاده شود.
- آرشیو پیام‌های گروه در صورت تنظیم `DATABASE_URL` در جدول مستقل و ایندکس‌شده PostgreSQL (`fxi_community_messages`) ذخیره می‌شود؛ تاریخچه محدود و قدیمی موجود در فایل JSON هنگام راه‌اندازی به‌صورت idempotent به جدول منتقل می‌شود و فقط پس از موفقیت انتقال از JSON سبک می‌شود. در نبود دیتابیس، حالت سازگار قبلی با حداکثر ۱۲۰ پیام اخیر برای هر گروه فعال می‌ماند.
- تاریخچه پنل مالک و پنل مالک گروه با صفحه‌بندی مبتنی بر شناسه پیام (keyset pagination) و جست‌وجوی متن/فرستنده ارائه می‌شود؛ در نتیجه برای مشاهده پیام‌های قدیمی، کل آرشیو یک‌باره در حافظه بارگذاری نمی‌شود. ویرایش و حذف پیام‌ها هم‌زمان در تلگرام و آرشیو ثبت می‌شود.

## نکات امنیتی و محدودیت‌ها

- مالک اصلی از `/login` وارد می‌شود و پس از احراز هویت به پنل مستقل `/owner` هدایت می‌شود. این پنل دسترسی کامل مالک را دارد.
- متقاضی برای درخواست مدیریت فقط نام کاربری و کد دعوت ۴ رقمی مالک را وارد می‌کند؛ سپس حساب تلگرام خود را با لینک Start اختصاصی به درخواست متصل می‌کند.
- مدیر پس از تأیید مالک، با نام کاربری کد ۶ رقمی یک‌بارمصرف دریافت می‌کند؛ کد به تلگرام متصل‌شده ارسال، پس از ۶۰ ثانیه منقضی و پس از ورود موفق مصرف می‌شود.
- مدیران ربات پس از ورود به پنل مستقل `/admin` می‌روند؛ دسترسی هر مدیر برای هر درخواست در سمت سرور کنترل می‌شود. تغییر سطح دسترسی نشست‌های قبلی را باطل می‌کند و به مدیر در تلگرام اطلاع می‌دهد؛ حذف مدیر نیز دسترسی API را فوراً لغو کرده و اعلان لغو دسترسی ارسال می‌کند. مدیر گروه به‌تنهایی مجوز ورود به پنل ربات ندارد.
- ادمین‌های عادی به‌صورت پیش‌فرض فقط نمای کلی را می‌بینند. سطح دسترسی هر ادمین از پنل تعیین می‌شود و مجوزها برای هر درخواست در سمت سرور بررسی می‌شوند؛ حذف ادمین دسترسی API را فوراً لغو می‌کند.
- مدیر دارای مجوز گروه‌ها و کانال‌ها می‌تواند فعالیت ربات را برای هر فضای ثبت‌شده جداگانه متوقف یا فعال کند. هنگام توقف، پردازش پیام‌های آن فضا و پیام خوشامدگویی متوقف می‌شود؛ این تنظیم، ربات را از گروه/کانال حذف نمی‌کند.
- مقدار `ADMIN_PANEL_URL` را روی آدرس پایهٔ HTTPS سرویس بگذار و `/admin` به انتهای آن اضافه نکن. ادمین باید قبلاً ربات را در تلگرام Start کرده باشد تا بتواند پیام خصوصی دریافت کند.
- دریافت کد مدیر دارای محدودیت تلاش و فاصلهٔ زمانی است. `SESSION_SECRET` را به یک مقدار تصادفی طولانی تغییر بده و فقط از طریق Environment میزبان نگه‌داری کن.
- کلیدهای API در پنل نمایش داده نمی‌شوند و باید از طریق متغیرهای محیطی میزبان مدیریت شوند.
- گزارش فعالیت مدیریتی برای عیب‌یابی و پیگیری تغییرات است؛ جایگزین سامانهٔ حسابرسی سازمانی نیست.
- آمار گروه و کانال از زمان اضافه‌شدن ربات و دریافت رویدادها جمع می‌شود؛ ربات به‌طور خودکار تاریخچهٔ قدیمی تلگرام را بازیابی نمی‌کند.
- برای اجرای قابلیت‌های مدیریتی، ربات باید مجوزهای لازم را در گروه داشته باشد؛ حذف یا محدودکردن اعضا و سنجاق‌کردن پیام نیز به دسترسی مدیریتی مناسب نیاز دارد.
- تنها OpenRouter برای مدل و تحلیل تصویر استفاده می‌شود؛ پیام صوتی در این نسخه غیرفعال است.


## کنترل کیفیت و تست

تست‌های آفلاین رگرسیون در مسیر `tests/test_fxi_core.py` قرار دارند و بدون اتصال به تلگرام یا OpenRouter اجرا می‌شوند:

```bash
python -m compileall -q .
python -m unittest discover -s ../tests -p "test_fxi_core.py" -v
```

GitHub Actions نحو Python، JavaScript پنل و صفحه ورود، import برنامه و مسیرهای اصلی احراز هویت را بررسی می‌کند. نتیجه موفق این بررسی‌ها به معنی تأیید عملکرد زنده همه قابلیت‌ها در تلگرام نیست؛ برای انتشار نهایی باید ربات در یک گروه آزمایشی نیز بررسی شود.

## ورود پنل مدیریت

- صفحهٔ ورود `/login` فقط برای مدیر ربات است؛ ورود و ثبت‌نام پنل برای مخاطبان عادی وجود ندارد.
- مالک اصلی با `ADMIN_PANEL_USERNAME` و `ADMIN_PANEL_PASSWORD` وارد `/login` می‌شود و پنل `/owner` را می‌بیند.
- مالک نام کاربری و رمز مدیر را خودش ثبت می‌کند؛ مدیر با همان دو مقدار وارد `/admin` می‌شود.
- نشست مدیر در کوکی HttpOnly و با اعتبار ۱۲ ساعت نگهداری می‌شود؛ تلاش‌های ناموفق ورود محدود می‌شوند.
- مدیران پنل فقط با نام کاربری و رمز ۴ کاراکتری اختصاصی که مالک ساخته وارد `/admin/login` می‌شوند؛ رمز با PBKDF2-HMAC-SHA256 و salt تصادفی هش می‌شود و نشست ۱۲ ساعته استفاده می‌شود.
- `SESSION_SECRET` را به یک مقدار تصادفی طولانی تغییر بده و فقط در Environment میزبان نگه‌داری کن.
- حساب جداگانه‌ای برای مخاطبان پنل ساخته نمی‌شود؛ مخاطبان ربات صرفاً کاربران تلگرام هستند و در بخش کاربران ربات نمایش داده می‌شوند.
- مدیر دارای مجوز «کاربران» می‌تواند دسترسی کاربر را از ربات مسدود یا دوباره فعال کند. کاربران مسدودشده پاسخ ربات دریافت نمی‌کنند و در پیام همگانی کاربران نیز گیرنده محسوب نمی‌شوند؛ این کاربر از گروه یا کانال تلگرام حذف نمی‌شود.
